# Random Pixels Generator

Генератор случайных RGB-изображений на PySide6 с процедурным анализом структуры
и многопроцессной генерацией.

## Возможности

- ширина и высота изображения;
- минимальный интервал между кадрами;
- настраиваемый порог MVP от 0 до 100;
- до 16 независимых параллелей через отдельные процессы;
- добавление/удаление параллелей прямо во время работы;
- отдельное превью, FPS и статистика для каждой параллели;
- MVP на каждом кадре;
- Robust только для кадров, прошедших MVP;
- автосохранение кадров, прошедших MVP;
- Top-10 MVP и максимум отдельно по каждой параллели;
- ручное сохранение текущего кадра любой параллели.

Каждый пиксель независимо получает R, G и B в диапазоне 0..255.

## Запуск

### Windows

```bat
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python main.py
```

### Linux / macOS

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python main.py
```

## Анализ

Для каждого процесса цикл выглядит так:

```text
random RGB
  -> MvpAnalyzer
  -> если MVP >= порога: RobustAnalyzer
  -> если включено автосохранение: сохранить MVP-кандидат
  -> следующий кадр
```

MVP — быстрый первый фильтр. Robust сравнивает пространственную структуру с
перемешанными версиями тех же пикселей. Score показывает необычность структуры,
а не семантический смысл изображения.

Один и тот же `Порог MVP` определяет передачу в Robust и автосохранение.
Порог, размеры, интервал, отображение и автосохранение можно менять во время работы;
обновлённая конфигурация рассылается всем процессам.

Автосохранение идёт раздельно:

```text
candidates/
  worker_01/
  worker_02/
  ...
```

## Параллельность

Кнопка `+ параллель` запускает ещё один независимый процесс, максимум 16.
У процесса собственные RNG, `AnalysisPipeline`, статистика и каталог кандидатов.

Процессы генерируют и анализируют без ограничения частотой UI. В главное окно
передаётся только свежий snapshot примерно 20 раз в секунду, чтобы Qt не стал
узким местом.

Численные библиотеки внутри каждого worker принудительно ограничены одним потоком:
идея — 16 процессов ≈ до 16 одновременно занятых CPU-ядер, а не 16 вложенных
пулов потоков.
